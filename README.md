# Fix0r / FC — сайт сообщества

Исходники [fix0r.ru](https://fix0r.ru): главная FC / TrustTheGame и кабинет ДКП
гильдии SleepingForest. Хостинг — PHP/MySQL; обновление GitHub само по себе
не загружает файлы на хостинг и не применяет SQL.

## Возможности

- Главная в стиле таверны: расписание эфиров, правила и разделы сообщества.
- Две темы — «Сумеречный лес» и «Лес и крем» — с переключателем и сохранением выбора
  в браузере для главной и ДКП.
- Встроенный плеер Twitch `fix0r`, переход «Прямая трансляция» в шапке,
  ссылки на Telegram, Twitch, TeamSpeak 3, Discord и Boosty.
- Регистрация с подтверждением email, роли участника, офицера и администратора.
  При выборе «Новый участник гильдии» игровой профиль создаётся после
  подтверждения email. Для прежних участников предусмотрена явная привязка.
- Состав гильдии: статус привязки и email для сотрудников, сортировка балансов,
  архивирование и восстановление участников.
- ДКП: начисления и списания с причиной, история и журнал действий.
- События: самоотметка игроков, проверка списка офицером, однократная выдача
  награды, отмена; ежедневные ЧВ с отключением и включением автосоздания.
- Аукционы: ставки, резервирование ДКП, продление при поздних ставках
  и автоматическое завершение. В кабинете — переключатель события/аукциона.
- Объявления: закрепление, срок действия, подтверждение прочтения;
  привязка Telegram и явная отправка объявления подписчикам администратором.

Красная точка у «Прямой трансляции» — оформление ссылки, а не проверка
онлайн-статуса канала. Плеер загружается без автозапуска; в узком контейнере
вместо него показана ссылка на Twitch. При смене домена нужно обновить
параметры `parent` в адресе плеера в `index.html`.

## Развёртывание и обновление

Нужны PHP 8.3 с PDO MySQL и Argon2id, MySQL 8, HTTPS и отправка почты
средствами хостинга. Для Telegram дополнительно нужны PHP cURL и исходящий
HTTPS-доступ к API Telegram.

Репозиторий рассчитан на обновление существующего ДКП. `dkp/schema.sql`
и миграций из `private/` недостаточно для установки полного ДКП с нуля:
исходные схемы переноса из бота, балансов, событий и аукционов здесь представлены
не полностью. Не добавляйте дамп рабочей базы с участниками для устранения
этого ограничения.

1. Перед обновлением сохраните резервную копию базы и заменяемых файлов.
2. Прочитайте инструкцию нужного модуля в `docs/` и импортируйте необходимые
   SQL-миграции в базу сайта через phpMyAdmin **до** загрузки зависящего от них PHP.
   Для переключателя ЧВ обязательна `private/01-event-schedule.sql`.
3. Загрузите файлы главной в `www/fix0r.ru/`, файлы ДКП — в `www/fix0r.ru/dkp/`.
   При обновлении главной загружайте и подключённые CSS/JS-файлы.
4. Сохраните рабочие `dkp/config.php`, `dkp/telegram_config.php` и свои значения
   в `dkp/cw_schedule.php`. Примеры конфигов не содержат рабочих реквизитов.
5. Проверьте страницы и задания Cron. Для CSS при необходимости обновите
   страницу с очисткой кэша (`Ctrl+F5`).

На сервере `config.php` создаётся по `config.example.php`; отдельный
`telegram_config.php` — по его примеру при подключении уведомлений.
Настоящие пароли и токены задаются только на хостинге.

Публикуйте только файлы сайта. `private/`, `tests/`, `docs/`, `.git`, README,
отчёты и резервные копии не должны находиться в общедоступном корне сайта.
Сохраните защитный `dkp/.htaccess`; её работу нужно проверять на конкретном хостинге.

## Планировщик

Два независимых задания, каждое с расписанием `* * * * *`:

```sh
/opt/php/8.3/bin/php "$HOME/www/fix0r.ru/dkp/auction_cron.php"
/opt/php/8.3/bin/php "$HOME/www/fix0r.ru/dkp/telegram_cron.php"
```

Это пути используемого хостинга; на другом сервере замените путь к PHP и сайту.
Первое задание завершает аукционы и создаёт ЧВ. Второе обрабатывает привязки
Telegram, отписки и очередь уведомлений; оно нужно при включённой интеграции.
Отключение автосоздания ЧВ выполняется кнопкой в разделе «События»:
**само задание `auction_cron.php` оставьте включённым**.

Для проверки конфигурации добавьте к соответствующей команде `--check`.
Этот режим не создаёт события, не завершает аукционы и не отправляет рассылку.
Проверка Telegram обращается к API и может сохранять служебные сведения о боте;
она не читает входящие обновления.

## Проверки и секреты

В `tests/` есть проверки на SQLite. Для автосоздания ЧВ:

```sh
php -d extension=pdo_sqlite tests/scheduled_events.php
```

Нужны PDO и PDO SQLite (если расширение уже включено, параметр `-d` не нужен).
Автоматического запуска тестов в GitHub Actions в текущей версии нет.
Локальные проверки не подтверждают установку MySQL, работу Cron на хостинге
и доставку реальных Telegram-сообщений.

Рабочие конфиги, `.env`, ключи, базы, дампы, архивы и журналы исключены через
`.gitignore`. Уже отслеживаемые файлы это правило не удаляет. SQL-миграции,
присутствующие в репозитории, содержат схему и служебные начальные значения;
дампы пользовательских данных публиковать нельзя.

[SECURITY_REVIEW.md](SECURITY_REVIEW.md) — историческая проверка исходного
архива от 16 сентября 2026 года, а не аудит всех последующих изменений.
