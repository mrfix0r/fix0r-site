# Ежедневные ЧВ и управление автосозданием

Cron создаёт события по времени Москвы (`Europe/Moscow`):

| Время | Название |
| --- | --- |
| 07:30 | Утреннее ЧВ |
| 15:30 | Дневное ЧВ |
| 20:30 | Вечернее ЧВ |

Событие появляется при первом запуске Cron после наступления его времени,
обычно в течение минуты. Часовой пояс хостинга не влияет. Автосоздание
не начисляет ДКП: состав проверяет и награду выдаёт офицер.

## Обновление существующего сайта

Нужен установленный ДКП с событиями, аукционами, журналом `fc_operations`
и общей блокировкой `fc_write_lock`.

1. Сохраните резервную копию базы и заменяемых файлов ДКП.
2. В phpMyAdmin выберите базу сайта и импортируйте
   [`private/01-event-schedule.sql`](../private/01-event-schedule.sql).
   **SQL обязателен для текущего переключателя.** Он создаёт
   `fc_event_schedule` с начальным состоянием «включено». Повторный импорт
   сохраняет уже выбранное состояние.
3. Если автосоздание ЧВ уже установлено и добавляется только переключатель,
   загрузите из обновления три файла в `www/fix0r.ru/dkp/` с заменой:
   `scheduled_events.php`, `events_view.php`, `index.php`.
   Сначала загрузите `scheduled_events.php`, затем представление и обработчик.
   Если пропущены другие обновления ДКП, предварительно установите их зависимости:
   текущий `index.php` также использует модули объявлений и Telegram.
4. Для установки автосоздания на уже работающий ДКП, где его ещё не было,
   дополнительно нужны `cw_schedule.php` и текущий `auction_cron.php`.
   Это не инструкция установки всего ДКП с нуля.
5. Не заменяйте рабочий `config.php`. Сохраните свои значения `cw_schedule.php`.
   Папку `private` на сайт не загружайте.
6. Оставьте запуск каждую минуту (`* * * * *`):

   ```sh
   /opt/php/8.3/bin/php "$HOME/www/fix0r.ru/dkp/auction_cron.php"
   ```

7. Откройте «События» под офицером или администратором. Над созданием ручного
   события появится блок «Автосоздание ЧВ» с текущим состоянием и кнопкой.

## Отключение и включение

- **«Отключить автосоздание»** останавливает создание всех трёх ежедневных ЧВ.
  Уже созданные события и их участники сохраняются, балансы не изменяются.
- **«Включить автосоздание»** возобновляет расписание для следующих слотов.
  События с временем, уже наступившим к моменту включения, не создаются
  задним числом, даже в пределах обычного окна восстановления.
- Ручное создание, самоотметка и выдача награды продолжают работать.
- Участники не могут переключать настройку. На сервере проверяются актуальные
  роль, подтверждение email и версия сеанса офицера/администратора.
- Устаревшая форма после другого изменения отклоняется. Повторная отправка
  старой формы не возвращает прежнее состояние.

**Не отключайте Cron целиком:** этот же скрипт завершает аукционы.
Отдельный `telegram_cron.php` не зависит от переключателя ЧВ.

Настройка хранится в базе. Сохранение настройки и создание события используют
одну блокировку: после сохранённого отключения последующие попытки создания
не проходят. Событие, успевшее создаться до отключения, остаётся в списке.
Переключения записываются в `fc_operations` с видом `cw_schedule`.

## Настройки сервера

[`dkp/cw_schedule.php`](../dkp/cw_schedule.php) содержит:

| Параметр | По умолчанию | Значение |
| --- | --- | --- |
| `enabled` | `true` | Разрешение автосоздания в конфигурации сервера |
| `creator_id` | `1` | ID подтверждённого аккаунта администратора — автора автособытий |
| `points` | `5` | Награда каждому; выдаётся вручную офицером |
| `catch_up_minutes` | `30` | Допустимая задержка создания после времени ЧВ |

Для работы нужны одновременно `enabled=true` в файле и включённое состояние
в `fc_event_schedule`. При `enabled=false` интерфейс показывает отключение
на сервере и не позволяет включить автосоздание. Сначала администратор должен
изменить конфигурацию. Для обычной паузы пользуйтесь кнопкой на сайте: она
также фиксирует момент возобновления, чтобы исключить пропущенные события.

## Поведение расписания

- При обычном сбое Cron до 30 минут включённый планировщик может создать ЧВ
  с исходным временем. Более старые слоты и предыдущие дни не восстанавливаются.
  После первого подключения действует то же окно. Пауза через кнопку —
  исключение: пропущенное за время паузы не восстанавливается.
- Повторный или одновременный запуск не создаёт дубль одного слота.
  Изменение названия/даты, выдача награды или отмена созданного события
  не приводят к повторному созданию исходного слота.
- Если на точное время уже существует ручное событие типа ЧВ, используется оно,
  включая закрытое или отменённое. Его награда, статус и состав не меняются.
- Старые открытые события автоматически не закрываются.
- Автосоздание записывается в журнал как `evt_auto` («Автоматическое ЧВ»).
  Ошибка задания ЧВ не препятствует попытке завершить аукционы, и наоборот.

## Проверка после установки

Если доступен терминал хостинга, выполните:

```sh
/opt/php/8.3/bin/php "$HOME/www/fix0r.ru/dkp/auction_cron.php" --check
```

Ожидаются сообщения `Auction scheduler configuration OK` и
`CW scheduler configuration OK`. Режим не создаёт события и не меняет балансы.
При отключённом автосоздании проверки его зависимостей сокращены; успешный
`--check` в этом состоянии не гарантирует готовность создания после включения.

Проверьте, что выбранное состояние сохраняется после обновления страницы.
При включённом расписании проверьте ближайшее новое ЧВ и запись в журнале.
Индикатор планировщика в аукционах относится **только к аукционам**:
создание ЧВ проверяется по событиям, журналу и выводу Cron.

Если блок сообщает, что настройка недоступна, проверьте импорт SQL и наличие
строки `id=1` в `fc_event_schedule`. Для создания также нужны подтверждённый
администратор `creator_id` и ранее установленные таблицы ДКП.

## Проверки разработчика

```sh
php -d extension=pdo_sqlite tests/scheduled_events.php
```

Текущий набор содержит 40 проверок: расписание, дубли, откат, роли и сеанс,
пауза/возобновление, устаревшие формы, журнал и приоритет конфигурации.
При подготовке переключателя также проверялись четыре одновременных запуска
отключения и создания. SQLite-проверки не заменяют проверку MySQL и Cron
на рабочем хостинге.
